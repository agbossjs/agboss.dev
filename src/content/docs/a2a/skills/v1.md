A data-only extension of A2A v1.0 (spec §4.6): the JSON Schemas of an AGBoss agent's skills — what
A2A's `AgentSkill` has no field for — and the skill a message runs.

## Declaration — the Agent Card

```json
{
  "uri": "https://agboss.dev/a2a/skills/v1",
  "required": false,
  "params": {
    "skills": {
      "<skill id>": {
        "input": { "type": "object", "properties": {} },
        "schemaHash": "<64 hex>",
        "reply": "task",
        "cardFileFields": "extension",
        "files": { "<file field>": { "list": false, "optional": false, "mediaTypes": ["application/pdf"] } },
        "outputs": { "<finish name>": { "type": "object" } },
        "outputFiles": { "<finish name>": { "<file field>": { "list": false, "optional": false, "mediaTypes": ["text/plain"] } } }
      }
    }
  }
}
```

- A skill's id is the exported `@WorkflowStart`'s name; `input` its input DTO's JSON Schema (`null`
  for a text start), `outputs` one schema per finish it can end at, `schemaHash` the input's hash —
  what `agboss check --federation` compares; `reply` how it answers: `"task"` (a task, its
  output an artifact) or `"message"` (a direct `Message`, no task; a client resends to it only
  within the mesh extension's `messageIdempotencyRetention`).
- File fields travel as file parts, never in a data part: no `input` or `outputs`
  schema asks for them. `cardFileFields: "extension"` declares them in `files` (the input) and
  `outputFiles` (by finish), present only when there are some; `"marker"` keeps each in its schema
  as `{ "x-agboss-file-part": { "list", "optional", "mediaTypes" }, "description" }`, never required.
- A client with DTOs compares them with these before anything is sent (`[a2a.schema-mismatch]`).

## DTO JSON Schemas

`input` and each entry of `outputs` are JSON Schema (draft 2020-12) documents generated from the
skill's DTO classes — the same ones the framework validates with — so a caller can validate before it
sends and check what comes back. A schema never asks for a file: a file field is in `files` /
`outputFiles` (or marked, with `cardFileFields: "marker"`). `schemaHash` is the SHA-256 of the
input schema, stable across builds; an equal hash is only a fast path, compatibility is decided
structurally.

## In a message — `message.metadata[uri].skill`

The skill the message runs: optional when the agent serves one, or sets a `defaultSkill` (what a
foreign caller that knows nothing of this extension gets); else required
(`-32602 a2a.skill-required`; an unknown one `a2a.unknown-skill`). A completed task's artifact names
its finish in `artifact.metadata[uri].finish`.

How AGBoss applications use it: the [A2A guide](https://github.com/agbossjs/agboss/wiki/A2A).

## Files — `message.metadata[uri].field`

A file part of a message fills a field of the skill's input DTO. A part names its field in
`metadata[uri].field`; parts without it fill the file fields in order. A file never travels in the
data part.

## The default skill

An agent that serves several skills may name a **default skill**. A message that names none —
what a foreign caller that knows nothing of this extension sends — runs it. The default is a server
setting, not part of the card: a caller that wants a certain skill names it. Without a default, a
message to an agent of several skills must name one (`-32602`, code `a2a.skill-required`).
