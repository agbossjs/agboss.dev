## Readable workflows. Verified before runtime.

In raw shared-state graphs, a router branch that skips a required producer compiles cleanly under `tsc` and fails only in production when that branch is taken. AGBoss tracks typed `@Dto` handoffs across every route and catches structural workflow mistakes before execution with `npx agboss check`:

<div class="agboss-proof-grid">
<div class="agboss-proof-card is-valid">
<div class="agboss-proof-head">
<span class="agboss-proof-badge is-valid">✓ Valid workflow</span>
<span class="agboss-proof-meta">Passes <code>agboss check</code></span>
</div>
<ul class="agboss-proof-points">
<li>Readable, declarative flow with explicit typed <code>@Dto</code> handoffs.</li>
<li>VIP orders route through <code>ApplyVipCouponAction</code> (<code>CouponDiscountDto</code>) before <code>RenderInvoiceAction</code>; standard orders route to <code>RenderStandardInvoiceAction</code>.</li>
</ul>

```ts title="missing-input-fixed.workflow.ts" no-check: concise workflow excerpt from 02-path-scope-proof
@Workflow({
  name: "missing-input-fixed-workflow",
  version: "0.1.0",
  flow: [
    start(MissingInputFixedStart)
      .returns(CheckoutRequestDto)
      .toRouter(TierRouter)
      .chooseOne(
        // VIP path produces CouponDiscountDto first
        route(ApplyVipCouponAction)
          .returns(CouponDiscountDto)
          .toAction(RenderInvoiceAction)
          .returns(InvoiceSummaryDto)
          .toFinish(MissingInputFixedFinish),
        // Standard path needs only CheckoutRequestDto
        route(RenderStandardInvoiceAction)
          .returns(InvoiceSummaryDto)
          .toFinish(MissingInputFixedFinish),
      ),
  ],
})
export class MissingInputFixedWorkflow {}
```

```text title="npx agboss check"
types: .agboss/types.d.ts
ok: cases/01-missing-input/agboss-fixed/application.ts
  — assembly, environment, application, prompts, types
```

<ul class="agboss-proof-points">

```ts title="missing-input-broken.workflow.ts" no-check: intentional [input.missing-on-path] example from 02-path-scope-proof
@Workflow({
  name: "missing-input-broken-workflow",
  version: "0.1.0",
  flow: [
    start(MissingInputBrokenStart)
      .returns(CheckoutRequestDto)
      .toRouter(TierBrokenRouter)
      .chooseOne(
        route(ApplyVipCouponAction)
          .returns(CouponDiscountDto)
          .toAction(RenderInvoiceAction),
        // Skips ApplyVipCouponAction (CouponDiscountDto)!
        route(RenderInvoiceAction),
      ),
    action(RenderInvoiceAction)
      .returns(InvoiceSummaryDto)
      .toFinish(MissingInputBrokenFinish),
  ],
})
export class MissingInputBrokenWorkflow {}
```

```text title="npx agboss check"
error [input.missing-on-path] missing-input-broken-workflow:
  render-invoice-action.coupon (CouponDiscountDto)
  is not produced on the path:
  missing-input-broken-workflow-start
    → tier-broken-router → render-invoice-action
```

## Three core capabilities

AGBoss layers structured application architecture on top of [LangGraph](https://www.langchain.com/langgraph)'s durable execution runtime:

<div class="agboss-pillars">
	<a class="agboss-mission-card agboss-pillar-link" href="/concepts/decorators/">
		<span class="agboss-mission-kicker">1 · DESIGN</span>
		<h3>Typed Components &amp; Declarative Workflows</h3>
		<p>Structure agent systems from focused TypeScript classes instead of monolithic shared state. Wire services with constructor dependency injection (<code>@Injectable</code>) and connect <code>@Agent</code>, <code>@Router</code>, and <code>@Action</code> steps through explicit <code>@Dto</code> contracts.</p>
		<span class="agboss-pillar-cta">Component Architecture →</span>
	</a>
	<a class="agboss-mission-card agboss-pillar-link" href="/concepts/verification-funnel/">
		<span class="agboss-mission-kicker">2 · VERIFY</span>
		<h3>Static Checking &amp; Deterministic Testing</h3>
		<p>Catch broken routes and test multi-agent behavior offline before calling a live model. Validate every workflow path at build time with <code>agboss check</code>, then run fast, deterministic unit and workflow tests with <code>testWith()</code> and recorded fixtures.</p>
		<span class="agboss-pillar-cta">Verification &amp; Testing →</span>
	</a>
	<a class="agboss-mission-card agboss-pillar-link" href="/guides/error-handling-and-rollback/">
		<span class="agboss-mission-kicker">3 · OPERATE</span>
		<h3>Reliable Execution &amp; Recovery</h3>
		<p>Run long-lived workflows in production with built-in fault tolerance and cost controls. Roll back failed side effects with <code>compensateWith</code> sagas, enforce <code>@Budget</code> limits, and resume paused or interrupted runs from persistent state.</p>
		<span class="agboss-pillar-cta">Production Reliability →</span>
	</a>
</div>
